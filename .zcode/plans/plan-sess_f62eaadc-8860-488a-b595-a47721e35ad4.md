# 用 foliate-js 渲染 EPUB，保留主谓宾着色 overlay

## Context

BioCN 现在的"阅读"是 Rust 解析器把章节拍平成纯文本段落（`src-tauri/src/reader/mod.rs`，故意丢弃 inline 标记），前端 `Reader.tsx` 只把这些文本加 `.svo-*` 颜色 span 排出来——粗斜体、图片、书籍自带 CSS 全部丢失。选型已定 **foliate-js**（npm `foliate-js@1.0.1`，MIT，GNOME Foliate 的引擎，WebKitGTK 是它的主力运行环境，与 Tauri Linux 一致；Android WebView 为 Chromium，同样可行）。

**架构原则：foliate 负责原书排版渲染，Rust 分析管线（段落文本 + UTF-16 offset 的 sentence/segment）原样保留；新增一个 JS overlay 模块把着色映射到渲染后的 DOM。** 已验证的关键事实：

- foliate 对畸形 XHTML 会自动降级 `text/html` 解析（`&nbsp;` 这类书籍能正常渲染）。
- foliate 的 section 文档是主页面创建的 blob URL → **继承主窗口 CSP**，书内图片/字体/CSS 需要 CSP 增补 `blob:`。
- 分析缓存按 `(weights, sentence文本)` 键控（`cache.rs` `sentences` 表），解析文本变化只会导致缓存 miss 重新分析，安全。
- `export.rs` 只依赖 Rust 解析结构和缓存，与前端渲染完全解耦，零改动。

用户已确认：**滚动模式**（`flow=scrolled`）、**尊重原书样式**（深色模式强制适配文字颜色）。

## 数据流

```
bookOpen(id) → BookView { id, title, chapters, filePath (新增) }
  → fetch(convertFileSrc(filePath)) → Blob
  → makeBook/view.open(blob) → view.init() → goTo(第一个非空章节)
  → foliate 'load' 事件 {doc, index} → bookChapter(id, index)（现有命令，缓存 Map）
  → overlay 模块: 遍历 doc 段落（镜像 Rust 解析规则）→ 规范化文本严格相等
  → DOM Range 定位 sentence/segment → 包 <span class="svo svo-*">
```

## 改动清单

### Rust（3 处，最小改动）

1. **`src-tauri/src/reading.rs`**：`BookView` 增加 `pub file_path: PathBuf` 字段（serde camelCase → `filePath`），在 `book_open` 里用现成的 `app.state::<Library>().book_file(id)` 填充（`store.rs:327-334`）。这是把存储的 `files/<id>.epub` 暴露给前端的唯一通道。
2. **`src-tauri/tauri.conf.json`**：
   - `app.security.assetProtocol`: `{ "enable": true, "scope": ["$APPDATA/library/files/*.epub"] }`
   - CSP 增补：`img-src`/`style-src`/`font-src`/`media-src` 各加 `blob:`（书内资源都是 foliate 生成的 blob URL），`connect-src` 加 `asset:`、`http://asset.localhost`、`https://asset.localhost`（Linux/macOS/Windows/Android 四种 scheme 形态）。`script-src` 不加 blob: —— 书籍自带脚本保持被 CSP 拦截（foliate README 的安全要求）。
3. **`src-tauri/src/reader/mod.rs`**：先跑 `cargo test` 确认 `a_non_breaking_space_collapses_like_any_other_space`（:727）的现状；按测试结果决定是否在 `html_entity`（:621）补 `"nbsp" => "\u{a0}"`，使 JS 侧规范化（U+00A0 → 空格）与 Rust 逐字对齐。缓存安全（句文本键控），不改缓存。

### 前端（新增 3 个模块 + 重写 Reader）

4. **`package.json`**：`foliate-js@1.0.1`（精确锁定；该 npm 包是上游 verbatim 转发）。
5. **`src/types/foliate-js.d.ts`**（新）：最小类型声明——`foliate-view` 元素、`relocate`/`load` 事件 payload、book/renderer 接口。官方无类型。
6. **`src/lib/foliate.ts`**（新）：foliate 访问隔离层。`openBook(blob)`、TOC 扁平化、`sectionIndex→goTo`、事件订阅的类型化包装。上游自述"API 不稳定"，所有 foliate 调用收在这里，未来升级只动一个文件。
7. **`src/lib/overlay.ts`**（新，纯逻辑可测）——本方案的核心：
   - **段落枚举**：`TreeWalker` 遍历 section doc，镜像 `reader/mod.rs` 的规则——`SKIPPED`（script/style/rt/rp/svg/math 子树跳过）、`PARAGRAPHS`+`CONTAINERS` 帧（`mod.rs:34-91`）、"子块结束父块文本"语义（:377-384）、`<br/>`→合成空格（:402-413）、空白折叠到单空格 + 首尾去空（镜像 `push_paragraph` :584-614，`replace(/\s+/gu,' ').trim()`）。
   - **顺序匹配**：枚举段落与 `ChapterView.paragraphs` 顺序对齐（同源同序），规范化文本**严格相等**才上色；不相等则该段保持不上色（宁缺勿错，绝不染错字）。
   - **绘制**：映射 analyzer 的 sentence/segment UTF-16 offset（`reading.ts` 已有类型）→ DOM Range；先算全段落所有 Range，再从文档尾部向前拆分 text node 并包 span（避免 offset 漂移）；`normal` 角色不包 span。沿用 `Reader.tsx:337-393` 的 gap 填充纪律。
   - **样式注入**：`view.renderer.setStyles(css)` 注入 `.svo-*` 六色值（与 `index.css:34-59`、`export.rs STYLESHEET` 三处互指注释）+ 深色模式文字颜色适配（尊重原书排版，只强制 color/background 适配主题）。
8. **`src/lib/overlay.test.ts`**（新）：把 `reader/mod.rs` tests 的 12 个用例移植成 DOM 版（fixture XHTML → DOMParser → 枚举+规范化结果逐一断言），加 Range/span 绘制用例。这是 parity 的回归防线。
9. **`src/components/Reader.tsx`** 重写（props 不变，`App.tsx` 零改动）：
   - 壳保留：header（书架/标题/目录）、键盘导航（方向键=章节）、缺模型 alert + `attempt` 重试（`modelsOpen` 关闭时重试逻辑照搬）。
   - body 换 `<foliate-view>`：滚动模式；`relocate` 事件更新"第 x/y 节"页脚。
   - 目录改用 foliate 真 TOC（嵌套 daisyUI menu），章节落地仍用 `ChapterSummary.paragraphs > 0` 找第一个有正文的章节。
   - 缺模型时书照常渲染 + alert 横幅（重试/打开设置），不再整页报错。
10. **`src/lib/reading.ts`**：`BookView` 类型加 `filePath: string`。
11. **`src/components/Reader.test.tsx`** 重写：mock `../lib/foliate`（假 view 对象）+ `../lib/reading`，保留现有测试模式（`waitFor`、键盘、错误文案断言）。

### 不改动

`export.rs`、`library/*`、`analyzer*`、`ModelSheet`、`HelixViewer`、`App.tsx`、`index.css` 的 svo 类（壳内不再用，但保留供 overlay 注入文案参照）。

## 验证

1. `cargo test`（src-tauri）——第 0 步，确认 nbsp 实体现状并按上文决策处理。
2. `yarn vitest run`——overlay parity 测试 + Reader 状态机。
3. `yarn build`——TS 通过。
4. `yarn tauri dev` 手工验收（需一本真实 EPUB，请用户提供）：原书排版/图片/斜体保留；着色结果与旧版一致（同一段对比）；目录跳转；章节导航；深浅色切换可读；导出对话框照常出书；断网状态打开已缓存章节。
5. Android：`yarn tauri android dev` 验证 asset protocol 在 WebView 下取到书文件（列为风险项，桌面先行）。

## 风险与对策

- **overlay 匹配率**：畸形 XHTML 走 foliate 的 text/html 降级路径时 DOM 结构可能与 Rust lenient 解析有出入 → 匹配失败的段落不上色但排版完好（严格相等门槛保证永不染错）。parity 测试锁住常见结构。
- **上游 API 不稳定**：foliate.ts 隔离层 + 锁版本。
- **书内脚本**：CSP `script-src` 不放行 blob:（default-src 'self' 拦截）+ foliate 的 per-item `load` 事件 `isScript → allow=false` 双保险。
