# EPUB 格式还原：标题层级 + 脚注（参考 EPUB.js 渲染思想）

## Context

**问题**：阅读器打开 EPUB 没有格式。根因在 Rust 解析器 `src-tauri/src/reader/mod.rs`：它把每章 XHTML 压成纯文本段落（`h1`-`h6` 只是普通 PARAGRAPHS 元素，标签名丢弃），前端 `Reader.tsx` 把所有段落渲染成 `<p>`。结果：章节标题和正文一样大；`aside[epub:type="footnote"]` 的脚注文本混进正文流；`a[epub:type="noteref"]` 的引用标记变成裸字符。

**EPUB.js 研究结论**（已读 `futurepress/epub.js` 源码 `src/managers/views/iframe.js`、`contents.js`、`section.js`）：
- 它把 spine 章节的**原始 XHTML 直接写进 sandboxed iframe**（`sandbox="allow-same-origin"`，默认无脚本），浏览器原生渲染全部标记 —— 标题、脚注、表格天然正确。
- 书内相对 URL（图片/CSS）改写成 blob URL（`contents.js` 的 `replaceLinks`），分页靠注入的 CSS 分栏。
- 脚注在核心里**完全不管**，是插件约定：点击 `epub:type="noteref"` 链接 → 弹出其引用的 `aside[epub:type="footnote"]` 内容。

**适配决策**：不能照搬 iframe 渲染 —— BioCN 的核心功能（主谓宾着色）依赖压平段落文本 + UTF-16 偏移（analyzer）+ `Placed` 字节映射（export.rs 重新拼回原书）。落地 EPUB.js "保留结构、交给浏览器渲染" 思想的最小路径：让**块类型和脚注结构**穿过现有管线，前端用原生 HTML 元素渲染（浏览器如何渲染 iframe 里的 h2/aside，我们就用 h2/弹窗渲染）。

## 改动

### 1. Rust 解析器 — `src-tauri/src/reader/mod.rs`

- **标题**：`Paragraph` 增加 `kind` 字段（枚举 `H1..H6`/`Body`，序列化为 `"h1".."h6"`/`"p"`）。`Frame` 已持有标签名（`Frame::new(name)`），flush 时映射：h1-h6 → 对应 kind，其余 → Body。容器直接产出的文本自然是 Body。
- **属性解析**（新增）：`Event::Start` 时用 `BytesStart::attributes()` 读 `id` 和 `epub:type`（属性 key 按冒号取 local name 比对 `type`，忽略前缀差异；值按空格分词）。
- **脚注捕获**：
  - 进入 `aside` 且 epub:type 含 `footnote`/`endnote`（含复数）→ 捕获模式：期间 `push_paragraph` 产物不进正文 `out`，拼进 `Chapter.footnotes`（新字段 `Vec<NoteBody { id, text }>`；无 `id` 属性则生成 `note-N`；多段用空格 join）。
  - 进入 `a` 且 epub:type 含 `noteref` → 记录 `href` 的 fragment 为 target；期间每个字符在 `Placed` 上标记 note 引用（新增字段，索引进章脚注表）。字符**保留在段落文本里**（分析器输入、导出字节映射完全不变）。
  - `Placed::synthetic` 等现有构造语义不变。
- **标记偏移**：`Paragraph` 增加 `note_refs: Vec<NoteRef { start, len, target }>`（UTF-16 偏移，供前端 DOM 定位）。`push_paragraph` 里 kept 与 text 1:1 对齐，遍历累计 `ch.len_utf16()` 即可（与 `crate::analysis::utf16::utf16_len` 同约定）。

### 2. IPC 层 — `src-tauri/src/reading.rs`

- `ChapterView` 改为 `{ index, title, paragraphs: Vec<ParagraphView>, footnotes: Vec<NoteView> }`，其中 `ParagraphView { kind, colored: ColoredParagraph, noteRefs }`（分析器产物 ColoredParagraph 不动，阅读器结构挂在旁边 —— 一个决定一处）。
- `book_chapter` 在 `colored()` 1:1 结果上 zip kind / noteRefs（映射严格按位置，见 analyzer.rs `assemble()` 331-360）。

### 3. 前端 — `src/lib/reading.ts` + `src/components/Reader.tsx`

- `reading.ts` 类型镜像 Rust（"field for field"，见其 4-5 行注释约定）。
- `Paragraph` 组件按 kind 选元素：h1-h6 → `<h1>`-`<h6>` + tailwind 排版类（如 `text-xl font-bold`、`mt-8`；daisyUI 无 heading 等价物，属允许的例外）；其余 → `<p>`。
- 拼片逻辑（现有按 UTF-16 offset 切片）在 noteRef 覆盖处把纯文本换成上标按钮（`btn btn-ghost btn-xs text-primary` + `sup`）；点击打开 daisyUI modal 显示脚注文本。
- 弹窗复用现有模式：`src/components/dialog.tsx` 的 `useDialog` + `ModalBackdrop`（ExportDialog/ModelSheet 已在用）。`noteRefs` 的 target 在 `footnotes` 里查不到 → 保持普通文本。键盘翻页已有 `dialog[open]` guard，弹窗打开时不会误翻页。

### 4. 测试（TDD：先写失败测试再实现）

- `reader/mod.rs`：aside(footnote) 文本进 footnotes 不进正文、无 id 生成 id；noteref 字符留正文且 note_refs 偏移/target 正确；`h2` kind 正确；**无 epub:type 的普通 aside 仍进正文流**（行为不变）；导出/分析输入文本与改动前一致。
- `reading.rs`：现有测试适配新 `ChapterView`，断言 kind/noteRefs/footnotes 序列化。
- `Reader.test.tsx`：更新 mock 形状（一处 mock，26-45 行）；新增：标题渲染为 `<h2>`；点击 noteref 打开弹窗显示脚注文本。
- 回归不变式：export.rs 重新 parse 同一 html（export.rs:350），`colored` 与 `paragraphs` 长度对齐不破坏 —— 现有 export 测试应全绿。

## 验证

1. `cd src-tauri && cargo test`
2. `yarn test`
3. `yarn build`
4. `yarn tauri dev` 打开一本带标题层级和脚注的 EPUB：标题有层级、脚注不混正文、点标记弹出注释。分小步提交（解析器 → IPC → 前端）。

## 范围外（明确不做）

- iframe 整章渲染（EPUB.js 原样方案）：会破坏着色管线和偏移/导出约束。
- 图片/表格/引用块的完整还原；EPUB 2 无 `epub:type` 的旧式尾注（保持现状，照旧显示在文末）；书内 CSS/字体注入。
